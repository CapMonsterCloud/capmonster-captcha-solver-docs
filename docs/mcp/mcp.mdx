# MCP


**Model Context Protocol (MCP)** позволяет AI-агентам подключаться к внешним инструментам и сервисам.

CapMonster Cloud MCP предоставляет агенту инструменты для работы с CAPTCHA.


<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Как работает MCP CapMonster Cloud</summary>

С помощью MCP AI-агент может определять тип CAPTCHA и параметры задачи, обращаться к документации CapMonster Cloud, создавать задачи и получать результаты решения. При этом конечная цель работы агента — не только решить CAPTCHA, но и корректно интегрировать этот процесс в проект пользователя.

Для работы с веб-страницей MCP CapMonster Cloud можно использовать вместе с браузерным MCP `mcp-patchright-mainworld`:

```text
AI-агент
├── capmonster → CapMonster Cloud API
└── patchright → браузер
```

`capmonster` отвечает за работу с CapMonster Cloud. `patchright` открывает страницу, помогает определить тип CAPTCHA и получить её параметры, а также применить готовое решение. Затем агент переносит проверенный сценарий в код проекта.

Типовой процесс, под который разработан [SKILL.md](https://github.com/pavelgrinkevich/captcha-mcp-test/blob/main/capmonster_agent/SKILL.md):

1. Получить URL целевой страницы.

2. Определить тип CAPTCHA.

3. Изучить документацию и определить обязательные параметры.

4. Получить параметры со страницы.

5. Отправить запрос в CapMonster Cloud.

6. Получить результат.

7. Применить результат на странице и интегрировать этот сценарий в код пользователя.

:::info Примечание
Используйте автоматизацию только на ресурсах, где у вас есть разрешение на такие действия: например, на собственном сайте, тестовом стенде или демонстрационной странице.
:::

## Быстрый старт

:::tip Скопируйте prompt в своего агента
Выберите prompt в соответствии со своим окружением — **Python / PyPI** или **TypeScript / npm** — и скопируйте его в Claude Code, Codex или другой AI-агент. Агент определит клиент и операционную систему, настроит `capmonster` и `patchright`, а затем проверит их работу.

Если автоматическая настройка не удалась, настройте MCP вручную по [инструкции](#ручная-настройка).

:::

```text
I want to integrate CapMonster Cloud into my code. Set up the required MCP
environment yourself, validate it, and then help me implement the integration
in my project.

1. SET UP MCP

First inspect the current AI client, operating system, project and existing MCP
configuration. Do not assume MCP has already been configured and do not assume
that a single configuration file is used in every client or scope.

If the required servers are missing, add them to the appropriate project-level
or user-level MCP configuration for the current client. Install missing runtime
dependencies when needed. Ask me only for data or permissions that you cannot
obtain yourself. Do not change unrelated settings.

Configure the CapMonster Cloud MCP server as `capmonster` using the published
PyPI package:

{ "command": "uvx", "args": ["captcha-mcp-test"], "env": { "CM_API_KEY": "..." } }

If CM_API_KEY is not already available, ask me to provide it through a secure
secret input supported by the client or to set it locally. Do not ask me to
paste the key into chat, print it, add it to source code or commit it.

When access to a live page is required, also configure the browser MCP server
as `patchright`:

{ "command": "npx", "args": ["-y", "mcp-patchright-mainworld"] }

If the client cannot reload MCP configuration automatically, tell me exactly
what must be restarted, then continue validation in a new session.

2. CAPMONSTER TOOLS

The capmonster server exposes:

- get_supported_tasks
- get_task_parameters
- get_docs
- create_task
- get_task_result
- get_task_result_wait
- get_actual_user_agent
- get_balance

Prefer get_task_result_wait over repeatedly calling get_task_result manually.

The patchright server is the browser layer. Use it only when you need to open
the target page, trigger the CAPTCHA, inspect DOM or network data, extract live
parameters, or apply the returned solution.

3. WORKFLOW SKILL

Fetch and follow this file:

https://raw.githubusercontent.com/pavelgrinkevich/captcha-mcp-test/main/capmonster_agent/SKILL.md

Use it as the workflow even if the current client has no first-class skill
feature. This workflow is designed for a developer integrating CapMonster
Cloud into application code:

1) get the target URL;
2) identify the CAPTCHA type;
3) read the relevant documentation and determine the required parameters;
4) extract those parameters from the page;
5) create the CapMonster Cloud request;
6) receive the result;
7) inject or otherwise apply the result in the page and implement the same flow
   in my code.

The goal is not merely to solve one CAPTCHA inside the agent's browser. The
goal is to integrate CapMonster Cloud correctly into my project and leave me
with working code.

4. DOCUMENTATION

Use capmonster.get_docs(url) and start from:

https://docs.capmonster.cloud/llms.txt

After identifying the CAPTCHA type, open only the page for that type and use it
to determine the exact task parameters, extraction method, createTask request,
getTaskResult response and solution format. Trust get_supported_tasks for the
actual list of supported task types.

Do not load https://docs.capmonster.cloud/llms-full.txt unless the complete
documentation is specifically required. If MCP documentation is unavailable or
a parameter needs verification, use:

https://api.capmonster.cloud/docs/swagger-ui/spec.js

5. VALIDATE AND INTEGRATE

Before changing my code:

- call get_supported_tasks;
- call get_balance;
- verify that get_docs can fetch https://docs.capmonster.cloud/llms.txt;
- if browser access is required, verify that patchright can open a web page.

If a check fails, diagnose the configuration and fix it when possible. Explain
the remaining blocker only if you cannot continue without my action.

Once the environment is ready, ask me for the target URL, the relevant project
or code files, how the CAPTCHA is triggered, and any proxy, authentication,
region, header or User-Agent requirements. Then implement and verify the
CapMonster Cloud integration in my code.
```

## Ручная настройка

Работать с агентом можно через Desktop-приложение, терминал, IDE или редактор кода. Для полного сценария рекомендуется подключить оба сервера: `capmonster` и `patchright`.

Выберите способ работы — CLI-агент или Desktop-приложение. В каждой вкладке приведена полная последовательность настройки.

<Tabs groupId="mcp-work-mode">
<TabItem value="cli" label="CLI-агент" default>

<span style={{ fontSize: "1.2em" }}>**Шаг 1. Установите AI-агент**</span>

<br />Для работы потребуется AI-агент или другое приложение с поддержкой MCP.

Если агент уже установлен, проверьте, что он запускается и доступен в системе.

Например, для Claude Code:

```bash
claude --version
```

Для Codex:

```bash
codex --version
```

Если команда не найдена, установите выбранный AI-агент согласно его официальной инструкции: для [Claude Code](https://code.claude.com/docs/en/setup), для [Codex](https://developers.openai.com/codex/cli).


После установки убедитесь, что агент запускается и поддерживает подключение локальных MCP-серверов.

:::tip Агент не найден после установки
Если терминал или IDE не видит установленный агент, полностью закройте и снова откройте терминал и среду разработки. Уже запущенные приложения могут использовать старое значение `PATH` и не видеть новую команду до перезапуска.
:::

<span style={{ fontSize: "1.2em" }}>**Шаг 2. Установите Node.js и при необходимости uv**</span>

<br />Для запуска MCP-серверов потребуются `npx` и, в зависимости от выбранной реализации CapMonster MCP, `uvx`.

**Node.js и npx**

:::warning Важно:
`patchright` запускается через `npx`, поэтому Node.js необходим независимо от выбранной реализации CapMonster MCP.
:::

Проверьте установку:

```bash
node --version
npm --version
npx --version
```

Если команды недоступны, установите Node.js.

`npm` и `npx` обычно устанавливаются вместе с Node.js, поэтому отдельно устанавливать `npx` не требуется.

Для работы рекомендуется использовать Node.js 18 или новее.

**uv и uvx**

Если вы планируете использовать Python/PyPI-версию `captcha-mcp-test`, также потребуется `uvx`.

Проверьте его наличие:

```bash
uvx --version
```

Если команда недоступна, установите `uv`.

После установки `uv` команда `uvx` также станет доступна.

Проверьте:

```bash
uv --version
uvx --version
```

:::info Примечание
Если вы используете TypeScript/npm-версию `captcha-mcp-test`, `uv` и `uvx` устанавливать не требуется.
:::

<span style={{ fontSize: "1.2em" }}>**Шаг 3. Получите API-ключ**</span>

<br />Для работы `capmonster` необходим API-ключ CapMonster Cloud.

Он передаётся MCP-серверу через переменную окружения:

```text
CM_API_KEY
```

<span style={{ fontSize: "1.2em" }}>**Шаг 4. Выберите реализацию CapMonster MCP**</span>


<br />Доступны две эквивалентные реализации `captcha-mcp-test`.

<Tabs>
<TabItem value="npm" label="npm — TypeScript" default>

Для этой версии используется `npx`.

MCP-сервер запускается командой:

```bash
npx -y captcha-mcp-test
```

</TabItem>

<TabItem value="python" label="PyPI — Python">

Для этой версии используется `uvx`.

MCP-сервер запускается командой:

```bash
uvx captcha-mcp-test
```

</TabItem>
</Tabs>

Устанавливать `captcha-mcp-test` как зависимость вашего проекта не требуется. По умолчанию MCP-клиент может запускать опубликованный пакет напрямую через `npx` или `uvx`.

<span style={{ fontSize: "1.1em" }}>**Установка пакетов через npm и pip**</span>

<br />По умолчанию предварительно устанавливать MCP-пакеты не требуется: их можно запускать напрямую через `npx` или `uvx`. Если вы хотите установить пакеты заранее, используйте один из вариантов ниже.

<Tabs>
<TabItem value="npm-install" label="npm" default>

**CapMonster Cloud MCP**

Установите `captcha-mcp-test` глобально через npm:

```bash
npm install -g captcha-mcp-test
```

Проверить установку можно командой:

```bash
npm list -g captcha-mcp-test
```

После установки для `capmonster` можно использовать:

```json
{
  "command": "captcha-mcp-test",
  "args": [],
  "env": {
    "CM_API_KEY": "YOUR_API_KEY"
  }
}
```

**Patchright MCP**

Если вы планируете использовать браузер для открытия страниц, получения параметров CAPTCHA и применения решения, установите `mcp-patchright-mainworld`:

```bash
npm install -g mcp-patchright-mainworld
```

Проверить установку можно командой:

```bash
npm list -g mcp-patchright-mainworld
```

Предварительная установка `mcp-patchright-mainworld` необязательна. Во всех примерах ниже его также можно запускать напрямую через:

```bash
npx -y mcp-patchright-mainworld
```

</TabItem>

<TabItem value="codex-cli" label="Codex CLI">

Codex CLI, расширение Codex для IDE и ChatGPT Desktop используют общую конфигурацию MCP. По умолчанию она хранится в файле `config.toml`:

- Windows: `%USERPROFILE%\.codex\config.toml`;
- macOS/Linux: `~/.codex/config.toml`.

Для подключения MCP-серверов используйте команду `codex mcp add` — Codex автоматически сохранит настройки в файле `config.toml`. Серверы `capmonster` и `patchright` необходимо добавить по отдельности, выполнив соответствующую команду для каждого из них.

<Tabs groupId="codex-mcp-os">
<TabItem value="codex-mcp-windows" label="Windows" default>

Откройте PowerShell или встроенный терминал IDE.

Для TypeScript/npm-версии `capmonster` выполните:

```powershell
codex mcp add capmonster --env CM_API_KEY=YOUR_API_KEY -- npx.cmd -y captcha-mcp-test
```

Для Python/PyPI-версии вместо этого выполните:

```powershell
codex mcp add capmonster --env CM_API_KEY=YOUR_API_KEY -- uvx captcha-mcp-test
```

Затем независимо от выбранной реализации добавьте `patchright`:

```powershell
codex mcp add patchright -- npx.cmd -y mcp-patchright-mainworld
```

На Windows используется `npx.cmd`, чтобы запуск MCP-сервера не зависел от политики выполнения PowerShell-скриптов для `npx.ps1`.

</TabItem>

<TabItem value="codex-mcp-macos-linux" label="macOS / Linux">

Откройте терминал.

Для TypeScript/npm-версии `capmonster` выполните:

```bash
codex mcp add capmonster --env CM_API_KEY=YOUR_API_KEY -- npx -y captcha-mcp-test
```

Для Python/PyPI-версии вместо этого выполните:

```bash
codex mcp add capmonster --env CM_API_KEY=YOUR_API_KEY -- uvx captcha-mcp-test
```

Затем независимо от выбранной реализации добавьте `patchright`:

```bash
codex mcp add patchright -- npx -y mcp-patchright-mainworld
```

</TabItem>
</Tabs>

Замените `YOUR_API_KEY` на API-ключ CapMonster Cloud. Не добавляйте реальный ключ в сообщения агента, примеры кода или публичный репозиторий.

Проверьте, что добавлены оба сервера:

```bash
codex mcp list
```

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Альтернативно: настроить серверы через config.toml</summary>

Для доверенного проекта конфигурацию также можно сохранить в `.codex/config.toml` в корне проекта. Проектный файл будет использоваться только после того, как проект отмечен как доверенный.

<Tabs>
<TabItem value="codex-cli-npm" label="TypeScript / npm" default>

```toml
[mcp_servers.capmonster]
command = "npx"
args = ["-y", "captcha-mcp-test"]

[mcp_servers.capmonster.env]
CM_API_KEY = "YOUR_API_KEY"

[mcp_servers.patchright]
command = "npx"
args = ["-y", "mcp-patchright-mainworld"]
```

</TabItem>

## Доступные инструменты

После подключения MCP-серверов инструменты становятся доступны AI-агенту автоматически. Вручную выбирать их обычно не требуется — агент вызывает нужные инструменты в зависимости от текущей задачи.

### CapMonster Cloud

`captcha-mcp-test` предоставляет следующие инструменты:

- `get_supported_tasks` — возвращает поддерживаемые типы задач CapMonster Cloud;
- `get_task_parameters(task_type)` — возвращает параметры выбранного типа задачи и схему решения;
- `get_docs(url, offset, limit, section)` — загружает документацию CapMonster Cloud;
- `create_task(task)` — создаёт задачу и возвращает `taskId`;
- `get_task_result(task_id)` — однократно проверяет статус задачи;
- `get_task_result_wait(task_id, timeout_seconds, poll_interval_seconds)` — ожидает завершения задачи автоматически;
- `get_actual_user_agent()` — возвращает актуальный Windows User-Agent;
- `get_balance()` — возвращает баланс аккаунта CapMonster Cloud.

### Patchright

`mcp-patchright-mainworld` предоставляет инструменты для работы с браузером. Агент получает доступ к ним через MCP-клиент и самостоятельно выбирает нужные действия.

Актуальный список инструментов доступен на странице пакета [mcp-patchright-mainworld](https://www.npmjs.com/package/mcp-patchright-mainworld).

## Устранение неполадок

:::tip Поручите диагностику агенту
Если настройка не работает, передайте агенту текст ошибки. Он может проверить runtime, команды запуска, MCP-конфигурации пользователя и проекта, а также предложить или выполнить необходимые исправления.
:::

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>MCP-сервер не запускается</summary>

Проверьте, что команда из конфигурации доступна в том же окружении, из которого запускается MCP-клиент:

<Tabs>
<TabItem value="troubleshooting-npm" label="TypeScript / npm" default>

```bash
node --version
npx --version
npx -y captcha-mcp-test
```

</TabItem>

<TabItem value="troubleshooting-python" label="Python / PyPI">

```bash
uvx --version
uvx captcha-mcp-test
```

</TabItem>
</Tabs>

Если команда запускается и остаётся без вывода, это не обязательно ошибка: STDIO MCP-сервер ожидает подключения клиента. Остановить тестовый запуск можно сочетанием клавиш `Ctrl+C`.

Также проверьте, что:

- в JSON-конфигурации нет комментариев, лишних запятых и незакрытых скобок;

- имена полей `mcpServers`, `command`, `args` и `env` указаны без ошибок;

- после изменения конфигурации MCP-клиент полностью перезапущен;

- загрузка пакета через `npx` или `uvx` не блокируется сетью, прокси, антивирусом или корпоративной политикой.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Команда <code>captcha-mcp-test</code> не найдена после установки пакета</summary>

Предварительно установленная CLI-команда должна быть доступна в `PATH` процесса, из которого запускается MCP-клиент.

Проверьте расположение команды:

<Tabs>
<TabItem value="command-path-windows" label="Windows" default>

```powershell
where.exe captcha-mcp-test
```

</TabItem>

<TabItem value="command-path-unix" label="macOS / Linux">

```bash
which captcha-mcp-test
```

</TabItem>
</Tabs>

Если терминал находит команду, а Desktop-приложение — нет, полностью закройте и снова откройте приложение. При необходимости укажите в поле `command` полный путь к исполняемому файлу.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Инструменты <code>capmonster</code> или <code>patchright</code> не отображаются</summary>

Попросите агента проверить, откуда текущая сессия загружает MCP-конфигурацию. Расположение зависит от клиента, области действия и способа подключения сервера:

- в Claude Code серверы могут быть настроены на уровне проекта или пользователя; конфигурация может находиться в `.mcp.json`, `.claude.json` или управляться командами Claude Code;

- Claude Desktop использует `claude_desktop_config.json`;

- Codex использует `~/.codex/config.toml`, `%USERPROFILE%\.codex\config.toml` или проектный `.codex/config.toml`;

- в ChatGPT Desktop локальные серверы также можно добавить через настройки MCP.

После исправления конфигурации полностью перезапустите клиент и откройте новую сессию. В Claude Code подключение можно проверить через `/mcp`, а в Codex — через `/mcp` или `codex mcp list`.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}><code>get_balance</code> возвращает ошибку</summary>

Попросите агента проверить конфигурацию `capmonster`. Обычно нужно убедиться, что:

- в переменной `CM_API_KEY` указан действующий API-ключ CapMonster Cloud;

- вместо ключа не осталось значение `YOUR_API_KEY`;

- ключ передан в блоке `env` сервера `capmonster`, а не `patchright`.

После изменения ключа перезапустите MCP-клиент. Агент сможет повторно проверить подключение и баланс.

Если баланс равен нулю, пополните его перед созданием задач.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}><code>get_docs</code> не загружает документацию</summary>

Попросите агента проверить сетевой доступ MCP-клиента к `https://docs.capmonster.cloud/` и загрузку файла:

```text
https://docs.capmonster.cloud/llms.txt
```

Если документация временно недоступна или требуется дополнительно проверить параметры задачи, агент может использовать спецификацию API:

```text
https://api.capmonster.cloud/docs/swagger-ui/spec.js
```

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}><code>patchright</code> не открывает страницу</summary>

Проверьте работу `node`, `npx` и команды запуска:

```bash
npx -y mcp-patchright-mainworld
```

Если странице требуются прокси, User-Agent или locale, передайте эти параметры агенту. Он сможет использовать их при запуске браузера через `patchright`.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Задача возвращает ошибку или сайт отклоняет решение</summary>

Передайте агенту текст ошибки и условия появления CAPTCHA. Для диагностики он может:

1. проверить поддерживаемый тип задачи;

2. получить актуальные параметры и схему решения;

3. открыть документацию для выбранного типа CAPTCHA;

4. повторно получить динамические параметры после перезагрузки или повторного вызова CAPTCHA;

5. проверить согласованность User-Agent, прокси, cookies, заголовков и Client Hints для CAPTCHA, привязанных к сессии;

6. убедиться, что результат применяется в формате, предусмотренном для конкретного типа CAPTCHA.

Не используйте устаревшие `challenge`, `token`, `data`, `blob` и другие одноразовые параметры.

`ERROR_INVALID_TASK` обычно указывает на некорректные или устаревшие параметры. `ERROR_CAPTCHA_UNSOLVABLE` может быть временной ошибкой — агент может проверить входные данные и создать новую задачу.

</details>

## Часто задаваемые вопросы

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Нужно ли вручную выбирать и вызывать MCP-инструменты?</summary>

Нет. После подключения MCP-серверов инструменты автоматически становятся доступны AI-агенту. Агент сам выбирает и вызывает их в зависимости от текущей задачи.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Обязательно ли подключать оба MCP-сервера?</summary>

Нет. `capmonster` можно использовать отдельно, если параметры CAPTCHA уже известны и работа с браузером не требуется. `patchright` нужен, когда агенту необходимо открыть страницу, получить параметры CAPTCHA или применить результат решения.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Какую реализацию выбрать: npm или Python?</summary>

Обе реализации `captcha-mcp-test` предоставляют одинаковые инструменты. Выберите вариант под своё окружение:

- npm — если уже установлены Node.js и `npx`;

- Python — если используется Python 3.11 или новее и установлен `uvx`.

Для `patchright` в любом случае необходимы Node.js и `npx`.

</details>


<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Где хранить API-ключ?</summary>

Передавайте API-ключ через переменную окружения `CM_API_KEY` в конфигурации сервера `capmonster`. Не добавляйте его в prompt, сообщения чата, примеры кода или публичный репозиторий.

Если конфигурационный файл содержит реальный ключ, исключите его из Git или используйте безопасное хранилище секретов, поддерживаемое MCP-клиентом.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Нужно ли отправлять prompt перед каждой CAPTCHA?</summary>

Нет. В рамках текущей сессии после настройки достаточно передавать новые URL, условия появления CAPTCHA и задачи по интеграции.

В новой сессии prompt рекомендуется отправить снова, если агент не сохраняет загруженные инструкции и результаты проверки окружения.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Как проверить, какие типы CAPTCHA поддерживаются?</summary>

Попросите агента определить поддерживаемые типы CAPTCHA. Для этого он может использовать `get_supported_tasks`, а для конкретной задачи — `get_task_parameters(task_type)` и документацию через `get_docs`.

</details>

<details style={{ fontWeight: 'normal' }}>
  <summary style={{ fontWeight: 'bold' }}>Нужно ли настраивать прокси в MCP-конфигурации?</summary>

Не обязательно. Если браузеру требуется прокси, передайте его параметры агенту — он сможет использовать их при запуске браузера без изменения MCP-конфигурации.

Если выбранный тип CAPTCHA требует собственного прокси, агент также должен передать его параметры в задаче CapMonster Cloud. Для CAPTCHA, привязанных к IP-адресу или сессии, в браузере и задаче должен использоваться один и тот же прокси.

</details>
